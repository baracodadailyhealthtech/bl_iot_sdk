BL70X Firmware Upgrade

Overview

The BL70X uses a dual-partition structure to perform firmware upgrades. Two independent firmware partitions (FW0 and FW1) are maintained in the flash. During upgrades, the new firmware is written to the inactive partition while the currently running firmware remains unchanged.

After a successful upgrade, the bootloader switches to the new partition at the next system reboot. If the upgrade fails, the system can roll back to the previous working partition (rollback feature enabled), ensuring the system remains functional.

Flash Layout

The BL70X series offers various flash capacities. Below is a layout example for a 1 MB configuration partition_cfg_1M.toml:

  • Boot Header:

    • Address: 0x0000

    • Size: 4 KB

    • Holds boot parameters, including flash configuration, firmware verification, and rollback settings.

  • Partition Table:

    • Address: 0x1000 and 0x2000

    • Size: 4 KB each

    • Dual-backup partition tables store flash partitions, with the latest table loaded at startup. Upon upgrade, the unused table is updated and designated as current.

  • Firmware (FW):

    • FW0:

      • Address: 0x3000

      • Size: 0x90000

    • FW1:

      • Address: 0x93000

      • Size: 0x66000

      • Dual-backup firmware, used to store the main and backup firmware images.

  • Manufacturing Firmware (MFG):

    • Address: 0x93000

    • Size: 0x66000

    • Stores manufacturing test firmware, which used for dual-firmware storage and automatic switching during manufacturing tests. Once manufacturing tests conclude, this firmware becomes inactive, and this space serves as the FW1 partition.

  • User Data (PSM):

    • Address: 0xF9000

    • Size: 8 KB

    • Stores user data. For EasyFlash, minimum size is 8 KB.

  • Media:

    • Address: 0xFB000

    • Size: 16 KB

    • Stores network data for Zigbee, it is reserved and can be removed for BLE applications.

  • Factory (Device Tree Information):

    • Address: 0xFF000

    • Size: 4 KB

    • Stores hardware configuration data, deletable if unused.

Firmware Upgrade Process

The BL70X supports multiple firmware upgrade methods, including UART upgrades, BLE OTA upgrades, and Zigbee OTA upgrades.

The following outlines the upgrade process and key APIs. For complete implementation, refer to the source code in hosal_ota.c, oad_main.c, and zbapp_otaClientHandler.c, which detail the firmware upgrade flows for each method.

  1. Software Flow

    • Retrieve the inactive firmware's flash address from the active partition table.

    • Write the new firmware to the inactive flash address.

    • Verify the content of the backup partition.

    • Update the inactive partition table, marking the new firmware as active.

    • Reboot the device. The bootloader will apply the new partition table and complete the OTA process.

  2. Key APIs:

    • Get Active Partition Table:

      ` pt_table_get_active_partition_need_lock() `

    • Write Firmware to Flash:

      • Retrieve the images address and size from active partition table:

        ` pt_table_get_active_entries_by_name() `

      • Erase the inactive flash partition:

        ` bflb_flash_erase() `

      • Write the firmware data:

        ` bflb_flash_write() `

    • Verify New Firmware:

      Calculate the SHA256 hash of the inactive flash partition, compare it with the hash stored in the firmware. If verification fails, the upgrade process should exit.

      ` utils_sha256_init() `

      ` utils_sha256_starts() `

      ` utils_sha256_update() `

      ` utils_sha256_finish() `

    • Update Partition Table:

      ` pt_table_update_entry() `

  • Reboot Device:

` GLB_SW_POR_Reset() `

  1. Generating Backup Firmware:

When using the devCube software, clicking the "Create & Download" button will automatically generate and save the following files:

` BouffaloLabDevCube-v1.8.9/chips/bl702/ota/FW_OTA.bin.xz.hash `

This file contains the firmware image and upgrade header information, as well as the SHA256 hash.
